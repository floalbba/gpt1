# MCP-инструменты: Заказы клиента (1С:ERP)

> Запросы выполняются от имени текущего пользователя.  
> Идентификаторы для модели — **наименование, код или артикул**. GUID не используйте.  
> Даты — `"YYYY-MM-DD"`. Суммы — decimal.

Партнёр в заказ не передаётся: его 1С берёт из контрагента.

---

## 1. `partners_search`

Вызови, когда нужно уточнить покупателя по имени, коду или ИНН.

**Параметры:**
| Параметр | Тип | Описание |
|---|---|---|
| `query` | string | Наименование, код или ИНН. Ищет контрагентов и партнёров |
| `limit` | number | Максимум строк, по умолчанию 20 |

**Ответ:**
```json
[{
  "code": "",
  "name": "Розничный покупатель",
  "full_name": "Розничный покупатель",
  "inn": "",
  "kind": "counterparty",
  "counterparty_code": "",
  "counterparty_name": "Розничный покупатель",
  "partner_code": "УТ-00000002",
  "partner_name": "Розничный покупатель"
}]
```

`kind`: `"counterparty"` или `"partner"`. В этой ERP у контрагента нет `Код` — идентификатор для заказа это `name` или `inn`. Строки `partner` с тем же именем не неоднозначность.

---

## 2. `nomenclature_search`

Вызови, когда пользователь назвал товар и нужны цена, остаток и код для `order_create`.

**Параметры:**
| Параметр | Тип | Описание |
|---|---|---|
| `query` | string | Наименование, артикул или код |
| `counterparty_name` | string | Контрагент (имя или код) — для цены по соглашению |
| `organization_name` | string | Организация — наименование |

**Ответ:**
```json
[{
  "code": "00-00000001",
  "name": "Товар А",
  "article": "А-001",
  "unit": "шт",
  "price": 4500.00,
  "stock": 42.0,
  "price_type": "Оптовая",
  "price_includes_vat": true,
  "vat_rate": 10,
  "vat_rate_name": "10%"
}]
```

Цена — только по виду цен соглашения контрагента (`price_type`). В заказ передавайте `code` или `article`, не GUID.

---

## 3. `order_create`

Вызови только после подтверждения сводки. Заказ записывается без проведения.

**Параметры:**
| Параметр | Тип | Обяз. | Описание |
|---|---|:---:|---|
| `counterparty_name` | string | да | Наименование или код контрагента |
| `delivery_date` | string | нет | Дата отгрузки `YYYY-MM-DD` |
| `organization_name` | string | нет | Организация — наименование |
| `warehouse_name` | string | нет | Склад — наименование |
| `comment` | string | нет | Комментарий |
| `items` | array | да | Позиции |
| `items[].nomenclature_code` | string | да | Код или артикул из поиска |
| `items[].quantity` | number | да | Количество |
| `items[].price` | number | нет | Цена из поиска; иначе по соглашению |

Шапка: организация, склад, соглашение, цены, НДС, этапы оплаты — типовыми процедурами ERP (как при изменении партнёра/номенклатуры в форме). Если имя/код неоднозначны, заказ не создаётся, в `errors` будет `hint`.

**Пример:**
```json
{
  "counterparty_name": "Розничный покупатель",
  "organization_name": "Торговый дом \"Комплексный\"",
  "warehouse_name": "Торговый зал",
  "delivery_date": "2026-08-29",
  "items": [
    { "nomenclature_code": "Арт-777788", "quantity": 2, "price": 72.00 }
  ]
}
```

**Ответ:** `number`, `amount` (Всего с НДС), `vat_amount` (сумма НДС), `discount_amount` (скидка), `price_type` (вид цен соглашения), `items` (в т.ч. `vat_amount`, `amount_with_vat`, `discount_amount`), `warnings`, `errors`. Всего без НДС = `amount` − `vat_amount` (в строке: `amount_with_vat` − `vat_amount`). Для проведения используйте `number`.

---

## 4. `order_get`

Вызови, чтобы показать уже созданный заказ. Параметр: `order_number`.

---

## 5. `order_update`

Вызови, чтобы изменить созданный заказ. Идентификатор — `order_number`. В `upsert_items` — `nomenclature_code`, не GUID.

---

## 6. `order_post`

Вызови сразу после успешного `order_create`. Параметры: `order_number`, `post` (`true` / `false`).

---

## Ошибки

```json
{
  "errors": [{
    "code": "VALIDATION_ERROR",
    "message": "Контрагент «Ромашка» не найден.",
    "hint": "Вызовите partners_search и уточните наименование, код или ИНН."
  }]
}
```

| Код | Описание |
|---|---|
| `ACCESS_DENIED` | Нет прав |
| `OBJECT_LOCKED` | Заблокирован другим пользователем |
| `ALREADY_POSTED` | Сначала отмените проведение |
| `VALIDATION_ERROR` | Ошибка заполнения; смотрите `message` и `hint` |

Поле `hint` — подсказка модели, какой инструмент вызвать дальше.
